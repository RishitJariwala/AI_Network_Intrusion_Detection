# Argus NIDS: Comprehensive Technical Documentation

## 1. System Overview

**Argus NIDS** is an advanced, production-grade Network Intrusion Detection System and Cyber Threat Intelligence platform developed for the MSc Artificial Intelligence & Cybersecurity program. It integrates:
- Supervised gradient boosting (XGBoost) and balanced Random Forests.
- Unsupervised anomaly detection (Isolation Forest) for zero-day defense.
- Mathematical explainability via SHAP (Shapley Additive exPlanations).
- Cyber Threat Intelligence (CTI) enrichment with multi-provider integration.
- Deterministic, multi-factor risk assessment engine.
- High-throughput asynchronous FastAPI backend.
- Professional SOC Streamlit dashboard designed according to Apple fluid interface principles.
- SQLAlchemy 2.0 ORM persistence supporting SQLite and PostgreSQL.

## 2. Dataset Specification (CICIDS2017)

The system was developed and validated on the official **CICIDS2017 TrafficLabelling** dataset generated by the Canadian Institute for Cybersecurity (UNB):
- **Raw Volume:** 3,119,345 flow records across 8 capture CSVs (1.1+ GB raw metadata).
- **Attributes:** 85 raw telemetry features including Flow ID, Source/Destination IPs, Ports, Timestamps, and Flow Duration.
- **Class Breakdown:**
  - `BENIGN`: 2,273,097 (72.87%)
  - `DoS Hulk`: 231,073 (7.41%)
  - `PortScan`: 158,930 (5.10%)
  - `DDoS`: 128,027 (4.10%)
  - `DoS GoldenEye`: 10,293 (0.33%)
  - `FTP-Patator`: 7,938 (0.25%)
  - `SSH-Patator`: 5,897 (0.19%)
  - `DoS slowloris`: 5,796 (0.18%)
  - `DoS Slowhttptest`: 5,499 (0.18%)
  - `Bot`: 1,966 (0.06%)
  - `Web Attack - Brute Force`: 1,507 (0.05%)
  - `Web Attack - XSS`: 652 (0.02%)
  - `Infiltration`: 36 (0.001%)
  - `Web Attack - Sql Injection`: 21 (0.0007%)
  - `Heartbleed`: 11 (0.0004%)
- **Data Quality Deficiencies Addressed:**
  - Repaired corrupted Latin-1 en-dashes (`0x96`) in Web Attack labels.
  - Handled 289,960 NaN labels and 2,867 infinite values in flow rate metrics.
  - Eliminated 8 constant features with zero variance.
  - Filtered 21 extreme collinear pairs (|r| > 0.98).

## 3. Anti-Leakage Feature Engineering Pipeline

### 3.1 Feature Exclusion
To prevent shortcut learning, the following identifier columns are stripped before feature extraction:
- `Flow ID`, `Source IP`, `Source Port`, `Destination IP`, `Timestamp`, `Protocol`, `source_file`, `Label`.

### 3.2 Selected Retained Features (48 Attributes)
The final model feature matrix uses 48 non-redundant, physically meaningful traffic attributes:
1. `ACK Flag Count`
2. `Active Max`, `Active Mean`, `Active Min`, `Active Std`
3. `Average Packet Size`
4. `Avg Bwd Segment Size`, `Avg Fwd Segment Size`
5. `Bwd Header Length`
6. `Bwd IAT Max`, `Bwd IAT Mean`, `Bwd IAT Min`, `Bwd IAT Std`, `Bwd IAT Total`
7. `Bwd Packet Length Max`, `Bwd Packet Length Min`, `Bwd Packets/s`
8. `CWE Flag Count`, `ECE Flag Count`, `FIN Flag Count`, `PSH Flag Count`, `URG Flag Count`, `Fwd PSH Flags`
9. `Destination Port`
10. `Down/Up Ratio`
11. `Flow Bytes/s`, `Flow Duration`, `Flow Packets/s`
12. `Flow IAT Max`, `Flow IAT Mean`, `Flow IAT Min`, `Flow IAT Std`
13. `Fwd Header Length`
14. `Fwd IAT Mean`, `Fwd IAT Min`, `Fwd IAT Std`
15. `Fwd Packet Length Max`, `Fwd Packet Length Min`, `Fwd Packet Length Std`
16. `Idle Std`
17. `Init_Win_bytes_backward`, `Init_Win_bytes_forward`
18. `Max Packet Length`, `Min Packet Length`, `Packet Length Variance`
19. `Subflow Bwd Bytes`, `Subflow Fwd Bytes`
20. `min_seg_size_forward`

### 3.3 Transformation Pipeline
```python
Pipeline(steps=[
    ('imputer', SimpleImputer(strategy='median')),
    ('scaler', RobustScaler(quantile_range=(5.0, 95.0), unit_variance=True))

```
*Note: All imputation medians and scaler quantiles are calculated strictly from the training split.*

## 5. Mathematical Formulations

### 5.1 Shapley Additive Explanations (SHAP)
For a predictive model $f$ and input feature vector $x$:
$$g(z') = \phi_0 + \sum_{i=1}^{M} \phi_i z_i'$$
Where the marginal Shapley contribution $\phi_i$ is computed as:
$$\phi_i(f, x) = \sum_{S \subseteq F \setminus \{i\}} \frac{|S|!(|F| - |S| - 1)!}{|F|!} \left[ f_x(S \cup \{i\}) - f_x(S) \right]$$

### 5.2 Dynamic Risk Scoring Formula
$$\text{Risk Score } R = \min\left(100, \text{BaseSeverity} \times P(\text{Attack}) + \Delta_{\text{anomaly}} + \Delta_{\text{port}} + \Delta_{\text{CTI}}\right)$$
Where:
- $\text{BaseSeverity} \in \{0, 45, 70, 75, 85, 90, 92, 98\}$
- $\Delta_{\text{anomaly}} = \min(15, \max(5, (\text{score} - 0.5) \times 30))$
- $\Delta_{\text{port}} = 10 \text{ if Destination Port } \in \{21, 22, 445, 3389, 8080\} \text{ else } 0$
- $\Delta_{\text{CTI}} = (\text{CTI Reputation} / 100) \times 15$

## 6. REST API Endpoint Specifications

Base URL: `http://localhost:8000`

### Endpoints
1. `GET /health`
   - Returns operational status, models loaded, active database.
2. `POST /predict`
   - Body: `NetworkFlowInput`
   - Returns: `PredictionResponse` (multiclass prediction, confidence, anomaly flag, risk score, recommended action).
3. `POST /predict/batch`
   - Body: `BatchFlowInput`
   - Vectorized high-throughput batch classification.
4. `POST /detect-anomalies`
   - Body: `NetworkFlowInput`
   - Returns: Isolation Forest outlier decision and normalized anomaly score.
5. `POST /explanations`
   - Body: `ExplanationRequest`
   - Returns: SHAP local attribution and feature importance ranking.
6. `GET /alerts`
   - Parameters: `limit`, `risk_level`, `min_risk`.
   - Returns: Historical alerts stored in SQLAlchemy ORM.
7. `GET /statistics`
   - Returns: Aggregated SOC threat metrics and attack distributions.
